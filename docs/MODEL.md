# Модель QALA

Источник: [датасет Astana Innovations](../tracks/astana%20innovations/dataset.txt). Код данных — [`src/lib/data.ts`](../src/lib/data.ts), расчёт — [`src/lib/engine.ts`](../src/lib/engine.ts). Версия модели: `astana-1.0`.

## Границы модели

Пять районов используют реальные названия, но исходные значения, цены и эффекты синтетические. Схема районов в интерфейсе иллюстративная и не отражает административные границы. Score — показатель заданной модели, не официальный индекс и не прогноз реального города.

## Допустимый сценарий

- Бюджет не больше 100 условных единиц; остаток не даёт бонуса.
- Ровно 5 различных мероприятий. Мера не может повторяться даже в другом районе.
- Не более 2 мер из одного направления.
- Район обязателен для районной меры и запрещён для городской.
- M1 и M3 несовместимы независимо от района.
- M4 и M7, а также M5 и M13 несовместимы в одном районе.
- Невалидный финальный набор не имеет Score. При редактировании разрешён неполный набор, но без превышения бюджета, повторов или конфликтов.

### Неоднозначность исходного условия

Общее условие можно прочитать как требование одного решения по каждому направлению. Подробный датасет разрешает максимум две меры из направления и содержит допустимый пример без транспорта. QALA следует подробному датасету: пять решений охватывают минимум три направления, но не обязательно все пять. Это явно указано в приложении и документации.

## Применение эффектов

Для района `d` и показателя `k`:

```text
I'[d,k] = clip(I[d,k] + sum(effect[m,k] × (8 − lag[m]) / 8) + synergy[d,k], 0, 100)
```

Горизонт — 8 кварталов. Городская мера оплачивается один раз и воздействует на все районы. Районная мера воздействует только на выбранный район. Все значения направлены одинаково: больше означает лучше.

Бонусы применяются один раз после основных эффектов и не масштабируются лагом:

| Сочетание | Где       | Бонус |
| --------- | --------- | ----- |
| M1 + M2   | Район M1  | T1 +2 |
| M10 + M12 | Район M10 | B1 +2 |
| M5 + M6   | Район M5  | E2 +2 |

Ограничение диапазона применяется после суммирования всех эффектов и бонусов. Порядок выбора решений не имеет значения.

## Итоговая оценка

```text
D[d] = sum(weight[k] × I'[d,k])
D_avg = sum(population_share[d] × D[d])
Score = 0.7 × D_avg + 0.3 × min(D[d]) − N_critical
```

| Показатель | T1   | T2   | E1   | E2   | S1   | S2   | B1   | B2   | C1   | C2   |
| ---------- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| Вес        | 0.10 | 0.10 | 0.09 | 0.11 | 0.11 | 0.11 | 0.09 | 0.09 | 0.10 | 0.10 |

`N_critical` — число пар «район × показатель» со значением **строго меньше 40**. Значение ровно 40 не штрафуется. Слабейший район определяется заново после расчёта. Вычисления не округляются на промежуточных шагах; округление до двух знаков применяется только для отображения. Поэтому сумма отображаемых округлённых вкладов может на 0,01 отличаться от отображаемого общего прироста.

## Контрольный пример

| Мера                      | Район      | Стоимость |
| ------------------------- | ---------- | --------: |
| M7 — школа и детсад       | Нура       |        24 |
| M8 — поликлиника          | Нура       |        20 |
| M10 — освещение и камеры  | Нура       |        12 |
| M12 — платформа обращений | Весь город |        14 |
| M5 — чистое топливо       | Сарыарка   |        25 |

| Значение                      |       До |    После |
| ----------------------------- | -------: | -------: |
| Среднее города                |  56.8624 |  58.0776 |
| Слабейший район               |    49.18 |  52.9625 |
| Число критических показателей |        2 |        0 |
| Score                         | 52.55768 | 56.54307 |
| Стоимость                     |        0 |       95 |

Школа поднимает S1 Нуры с 38 до 48; поликлиника — S2 с 35 до 43.75. Два штрафа исчезают. Синергия M10 + M12 добавляет B1 ещё 2 пункта.

## Объяснение вклада: точные значения Шепли

Простой независимый вклад не учитывает сочетания мер, переход через критический порог и смену слабейшего района. Поэтому QALA вычисляет точный вклад Шепли для каждой из пяти мер.

Для меры `i` рассматриваются все поднаборы `S` остальных мер. Её дополнительный вклад `Score(S ∪ {i}) − Score(S)` умножается на `|S|! × (n−|S|−1)! / n!`. Затем значения суммируются.

При пяти решениях достаточно посчитать 32 поднабора. Их оценки — внутренние промежуточные расчёты для объяснения; они не являются допустимыми финальными сценариями. Сумма вкладов совпадает с изменением Score относительно исходного города с точностью вычислений.

## Поиск альтернативы

Для каждой из пяти позиций алгоритм перебирает все мероприятия и допустимые районы, валидирует получившийся набор и рассчитывает результат. Выбирается лучшая строго положительная замена; при одинаковом Score предпочтение получает меньшая стоимость.

Для контрольного примера замена M5 в Сарыарке на M3 в Нуре даёт **Score 57.20556**, стоимость **100**, прирост **0.66249**. При этом оценка Сарыарки относительно текущего сценария уменьшается на **1.2125**, а Нуры увеличивается на **2.02**. Приложение показывает этот компромисс до применения замены.

Это полный поиск в окрестности **одной замены**, а не глобальный оптимизатор. Отсутствие улучшения одной заменой не исключает улучшение несколькими заменами. Предложение повышает целевую оценку, но не обязано улучшать каждый район или показатель.
