# Архитектура и AI

```mermaid
flowchart LR
  User[Пользователь] --> UI[React: обзор / выбор / результат]
  UI --> Rules[Детерминированный валидатор]
  Rules --> Engine[Расчёт Score]
  Engine --> Explain[Шепли + перебор одной замены]
  Explain --> Local[Локальный расчётный разбор]
  UI -->|Пять решений, без баллов| API[POST /api/analyze]
  API --> Rules
  API -->|Повторный расчёт на сервере| Facts[Расчётные факты и правила]
  Facts --> OpenAI[OpenAI Responses API]
  OpenAI --> Schema[Zod: структурированный ответ + ID фактов]
  Schema --> UI
  Local --> UI
  UI --> Chat[POST /api/planner]
  Chat --> Intent[OpenAI: изменения условий]
  Intent --> Conditions[Сохранение ограничений]
  Conditions --> Search[Полный перебор]
  Search --> Checked[Проверенные числа и сравнение]
  Checked --> UI
  Chat --> Delay[Эксперимент задержки]
  Delay --> Checked
```

## Модули

| Путь                           | Ответственность                                           |
| ------------------------------ | --------------------------------------------------------- |
| `src/lib/data.ts`              | Типизированный датасет, ограничения, контрольные сценарии |
| `src/lib/engine.ts`            | Валидация, эффекты, Score, вклад Шепли, поиск замены      |
| `src/lib/report.ts`            | Факты для объяснения и локальный разбор                   |
| `src/components/overview.tsx`  | Обзор и выбор района                                      |
| `src/components/builder.tsx`   | Каталог мер, ограничения и бюджет                         |
| `src/components/results.tsx`   | Сравнение, вклад, альтернативы, AI и таблица              |
| `src/components/simulator.tsx` | Навигация, сохранение, запросы, экспорт                   |
| `src/app/api/analyze/route.ts` | Серверная проверка, Responses API, кэш и fallback         |
| `src/app/api/status/route.ts`  | Признак настройки AI без раскрытия ключа                  |

Одна Next.js-программа запускает интерфейс и сервер. База данных, внешняя карта и отдельный Python-сервис не требуются. Шрифты устанавливаются через npm и отдаются локально. Сценарий и один набор для сравнения сохраняются в `localStorage` с версией формата. Ссылка кодирует только ID выбранных мер и районов.

## Роль OpenAI

Используется официальный JavaScript SDK, **Responses API** и **Structured Outputs** через `zodTextFormat`. Модель по умолчанию — `gpt-4.1-mini`; её можно изменить через `OPENAI_MODEL` на доступную модель, поддерживающую этот интерфейс.

AI получает рассчитанные факты, а не задачу вычислить результат: бюджет, Score до/после, изменения районов, критические значения, вклад Шепли, лаги, неизменённые показатели и последствия проверенной альтернативы. Модель формирует краткий вывод, сильные стороны, риски и рекомендацию. Каждый тезис ссылается на ID фактов; пользователь может раскрыть их прямо в интерфейсе.

Сервер проверяет структуру ответа и существование ID. **Это не автоматическое доказательство истинности каждого предложения LLM.** Ошибочные интерпретации возможны; исходные расчётные факты остаются видимыми, а числовая оценка никогда не берётся из ответа AI. Промпт ограничивает рекомендации проверенной альтернативой и запрещает перенос выводов на реальный город.

Мы не заявляем мультиагентную систему. В отчёте используется один аналитический вызов. В чате модель возвращает типизированное намерение: подбор, вопрос, задержка или уточнение. Подбор и эксперимент завершаются расчётом в коде; их числовой текст формируется программно. Для свободного вопроса второй вызов LLM получает заново рассчитанные факты.

## Диалог и полный поиск

`planner.ts` выполняет полный перебор; `planning-intent.ts` применяет изменения условий; `resilience.ts` моделирует задержки; `/api/planner` связывает эти модули с OpenAI. Интерфейс находится в `planner-chat.tsx` и `resilience-panel.tsx`.

Модель предлагает операции добавления/снятия закреплений и исключений, явного сброса и смены цели. Неупомянутые условия сохраняются сервером. Для снятия требуется фраза из последнего сообщения с явным указанием отмены; неоднозначность возвращается как уточнение. Перенос закреплённой меры в другой район без снятия прежнего закрепления отклоняется. Это ограниченная проверка, а не универсальное доказательство понимания естественного языка. Условия видны и редактируются вручную; применение только по кнопке.

«Помочь самому слабому району» максимизирует минимум районных баллов после решения. «Помочь Нуре» максимизирует конкретную Нуру: при её росте самым слабым может стать другой район. Формула официального Score сохраняется.

DFS перебирает наборы мер и назначения районов, отсекая только нарушения правил или условий. Нет отсечения по предполагаемой полезности. Без дополнительных условий остаётся **694395** допустимых планов. Быстрый расчёт использует плоский массив показателей, затем синергии, clip, веса, минимум районов и штраф. Победители пересчитываются основным `simulate()`. Независимая проверка сверила все допустимые планы; регрессионные тесты сохраняют независимые проверки ограниченных пространств по всем целям.

Выбираются победители по основной цели и до двух дополнительных. При равенстве сравниваются официальный Score, затем стоимость. Совпавшие наборы объединяются. Это победители по конкретным целям, не полный фронт Парето.

В API передаются последние восемь сообщений, актуальные условия, текущие решения и до трёх предыдущих кандидатов. История сохраняется при переключении экранов вкладки, но после перезагрузки начинается заново. Баллы не берутся из старых реплик: сценарии пересчитываются сервером.

## Поведение при недоступном AI

Без API-ключа, при таймауте, ошибке провайдера, отказе или некорректных ссылках на факты приложение показывает явно обозначенный **разбор по правилам модели**. Score, сравнение, Шепли, альтернатива и экспорт работают независимо от OpenAI. Локальный текст не выдаётся за ответ AI.

API имеет таймаут 25 секунд и не делает автоматических повторов. Кэш хранит до 100 ответов на 30 минут. Ограничение — 6 новых AI-запросов в минуту и 2 параллельных запроса на процесс. Повторный запрос того же набора обычно использует кэш; после перезапуска сервера кэш пуст.

Это лимиты `/api/analyze`. У `/api/planner` отдельный лимит 8 диалоговых запросов в минуту и 2 параллельных; каждый вызов модели имеет таймаут 20 секунд без повторов. Кэш поиска ограничен 30 наборами условий. Ручной подбор не использует LLM. Без ключа свободный диалог явно недоступен; приложение не имитирует понимание текста заглушкой.

## Данные и границы доступа

- `OPENAI_API_KEY` читается только сервером из `.env.local`. В Git и браузер ключ не передаётся.
- В аналитическом отчёте отправляется синтетический сценарий. В чате дополнительно передаются сообщения и условия. Лишние поля отбрасываются; системные роли от клиента не принимаются.
- Клиентские баллы не принимаются: сервер заново валидирует и рассчитывает сценарий.
- Тело запроса ограничено 4096 байт для анализа и 32768 байт для чата; переполнение прекращает чтение потока.
- Для браузерных запросов проверяется соответствие Origin входному Host.
- Вызовы OpenAI используют `store: false`; это настройка сохранения Response, а не обещание особого режима хранения данных у провайдера.
- Сообщения SDK не возвращаются пользователю, чтобы не раскрывать служебные данные.

Приложение по умолчанию слушает только `127.0.0.1`. Аутентификации нет; лимиты и кэш локальны для процесса. Для открытого многопользовательского размещения нужны контроль доступа, общий лимитер и бюджет API. Ссылка на сценарий работает у получателя только при доступе к тому же экземпляру приложения.
