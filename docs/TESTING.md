# Проверка решения

## Автоматическая проверка

```bash
npm ci
npm run check
```

`check` запускает TypeScript, Vitest и production-сборку. OpenAI-ключ не нужен. Тесты используют реальные HTTP-обработчики; ответы внешнего интерпретатора в регрессионных проверках заменены контролируемыми результатами. Платные запросы не отправляются. `npm run demo:verify` отдельно проверяет числа демонстрации.

GitHub Actions настроен на Node.js 24 / Ubuntu и проверку форматирования. На 23 сентября 2026 запуск заданий заблокирован биллингом аккаунта владельца репозитория: GitHub сообщает `The job was not started because your account is locked due to a billing issue`. Это не успешный CI-прогон. Проверки выполняются локально на Windows, Node.js 24.

## Ручной сценарий проверки

1. Запустите `npm run dev`, откройте `http://127.0.0.1:3000`.
2. Откройте «Обзор города» и выберите несколько районов. Оценка, описание и показатели должны соответствовать выбору.
3. Нажмите **«Посмотреть пример»**. Выбрано пять мер, потрачено 95 единиц.
4. Нажмите **«Рассчитать сценарий»**: Score **56,54**, критических значений **0**.
5. Изучите вклад мер и раскройте методику Шепли.
6. В блоке альтернативы проверьте компромисс: Сарыарка **−1,21**, Нура **+2,02** относительно текущего сценария.
7. Нажмите **«Применить замену»**: Score **57,21**, бюджет **100**. Предыдущий сценарий автоматически становится основой сравнения.
8. Вернитесь к выбору и удалите одну меру. Финальный расчёт недоступен, пока не выбраны пять допустимых мер.
9. Проверьте блокировку шестого решения, превышения бюджета, третьей меры одного направления и конфликта парка со школой в одном районе.
10. Скачайте JSON, сравните точные значения с интерфейсом. Перезагрузите страницу: выбранные меры сохраняются.
11. Скопируйте ссылку на результат и откройте в другой вкладке того же приложения: сценарий восстанавливается.

## Проверка AI

Скопируйте `.env.example` в `.env.local`, укажите действующий ключ и перезапустите сервер. Нажмите **«Получить AI-анализ»**. При успехе источник отчёта обозначен как `OpenAI · <модель>`. Раскройте факты под тезисами и сравните их с расчётом.

Удалите ключ из локального файла и перезапустите сервер, чтобы проверить режим без OpenAI: числовые результаты не изменятся, источник будет явно обозначен как разбор по правилам модели. Живой ответ LLM не входит в детерминированные unit-тесты; доступность зависит от ключа, модели, сети и лимитов аккаунта.

## Интерфейс

Проверка обновлённого рабочего экрана 23 сентября 2026: **56 тестов**, TypeScript и production-сборка прошли; форматирование проверено. В браузере проверены 1440 × 1100 и 390 × 844, живой OpenAI-поиск, Markdown-таблица, сохранение только после применения и синхронизация карты с изменением задержки. Axe не обнаружил нарушений на проверенных экранах; SVG-контраст отмечен инструментом как требующий ручной оценки. Скриншоты в `docs/screenshots/` сняты с локальной production-сборки.

Дополнительный маршрут нового рабочего экрана: выполнить поиск → переключить два предпросмотра → проверить, что сохранённый сценарий не изменился → запустить задержку → проверить одинаковые значения на карте и в панели эксперимента → вернуться без задержки → применить план кнопкой → открыть отчёт. Повторный подбор сравнивается с принятым планом, а не с предыдущим предпросмотром; это закреплено регрессионным тестом API. Для черновика из 1–4 мер итоговый Score не показывается.

Markdown проверяется на семантическое отображение выделений, списков и таблиц, блокирование сырого HTML, опасных ссылок и удалённых изображений. SVG-подписи карты требуют ручной оценки контраста: axe не определяет их фон автоматически.

Проверяются широкий экран 1440 px и мобильный 390 px, основной путь, сравнение, ограничения и доступность через axe-core. Горизонтальная прокрутка предусмотрена только внутри таблицы десяти показателей. Автоматический аудит не заменяет полноценную проверку экранным диктором.
